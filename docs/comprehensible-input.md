# 90% 法則：可理解輸入的量化

實作在 [`crates/wordforge-core/src/coverage.rs`](../crates/wordforge-core/src/coverage.rs)。

## 背後的想法

Krashen 的輸入假說主張，語言習得發生在理解「略高於現有程度」的輸入時（i+1）。
問題是「略高」到底是多少？後續的詞彙研究給出了可操作的數字：

| 已知詞覆蓋率 | 實際體驗 |
| --- | --- |
| 100% | 完全沒有新東西，只練流暢度 |
| 98% | 延伸閱讀的理想值，不查字典也能懂 |
| 95% | 可以讀，但需要一點推敲 |
| 90% | 精讀區間，需要詞彙表輔助 |
| < 90% | 閱讀斷裂成查字典 |

Wordforge 的 `CoverageBand` 就是這張表：

```rust
> 0.98        → TooEasy
0.95 ~ 0.98   → Optimal        ← 預設目標
0.90 ~ 0.95   → Challenging    ← 精讀模式
< 0.90        → TooHard
```

注意這裡算的是**詞元（token）覆蓋率**而不是相異詞（type）覆蓋率。
一篇文章 300 個詞裡有 12 個生詞詞元，就是 96% 覆蓋率——
即使那 12 個詞元其實只是 6 個生詞各出現兩次。

## 產生前：算出額度

```rust
// 300 詞的文章，目標 96% 覆蓋率
let budget = coverage::unknown_token_budget(300, 0.96);   // → 12 個生詞詞元
let words  = coverage::new_word_budget(300, 0.96, 2);     // → 6 個新詞，各出現 2 次
```

**為什麼每個新詞要重複出現**：一個詞只出現一次，讀者只能猜；
出現兩三次於不同上下文，才有機會歸納出意思。這也是為什麼
prompt 明確要求「每個新詞自然地出現 2 次以上」。

## 挑哪些新詞

`select_target_words` 的排序：

1. **教材指定的字優先** — 使用者匯入國中課本，就是為了考課本的字
2. **其次依詞頻** — 常用字的投資報酬率遠高於冷僻字
3. **已經會的字直接排除**

詞頻為什麼重要：英文最常用的 2000 個詞就覆蓋一般文本約 80% 的詞元，
5000 詞約 88%，要到 8000 詞才接近 95%。
曲線越後面越平——這就是為什麼背完基礎兩千字之後，
進步會突然感覺變慢，也是為什麼「按詞頻學」在初期特別有效。

## 產生後：驗收

**這一步是整個機制的核心。** Prompt 裡寫「生詞不要超過 12 個」，
模型只會大致遵守。真正的保證是產生之後本地重算：

```rust
let cov = coverage::analyze(&passage, &known, |w| lookup_lemma(w));
if !cov.band().is_usable() {
    // 帶著實際數字與超標的詞重試
    let retry = prompts::coverage_retry(cov.ratio(), target, &offenders);
}
```

`coverage_retry` 會把**具體是哪些詞超標**告訴模型。
只說「太難了請重寫」，模型往往換一批同樣難的字；
指名 `ubiquitous`、`paradigm` 要換掉，成功率高得多。

重試上限建議 2 次。連續失敗代表目標詞選得太難，
應該退回去換一批更常用的新詞，而不是無限重試燒 token。

## 邊界情況

- **查不到 lemma 的詞一律算未知**。這會讓覆蓋率偏保守（低估），
  是刻意的：寧可文章太簡單，也不要讓學習者撞牆。
- **空文章的覆蓋率是 0.0**，判定為 `TooHard`。
  這樣「產生失敗」不會意外通過驗收。
- **專有名詞**目前也算未知詞。人名地名確實會增加閱讀負擔，
  但如果之後發現這讓文章過度簡化，可以加入白名單機制。

## 中日韓的斷詞

`text::tokenize` 用 Unicode 的 word boundary 規則，
對拉丁語系正確，但中日韓沒有空格，會把整句切成一塊。
要支援中文或日文學習，需要在 `wordforge-dict` 接上分詞器
（jieba / lindera），目前尚未處理。
