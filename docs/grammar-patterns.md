# 句型與難度上限

## 這個功能在解決什麼

出題的難度原本只有**詞彙**那一半有依據：

| | 有沒有依據 | 怎麼保證的 |
| --- | --- | --- |
| 生詞多寡 | 有 | `measure_coverage()` 本地實算，不合格就退回重寫 |
| 指派的字有沒有用上 | 有 | `lemmas::forms` 拿整個詞族比對目標語言那一句 |
| **句型難易** | **原本完全沒有** | prompt 只寫「句子要自然、日常」 |

結果是：一篇每個字都認得的文章，照樣可以整篇都是分詞構句與假設語氣。
使用者的症狀是「每一題都錯」，而畫面上每一題都是好題目——
這是這個專案最熟悉的一種壞法。

現在補上的是那一半：句型變成**本地跑得動的偵測器**，
於是「這句超出他的程度」與「這句有沒有真的練到那個句型」
都變成可以在本地驗收的事實，而不是 prompt 裡的一句請求。

## 兩層檢查，缺一不可

| 層 | 抓什麼 | 覆蓋範圍 |
| --- | --- | --- |
| 句型偵測 | 命中「超過上限」的句型 | 只抓**收錄過的**句型 |
| 複雜度 | 句子太長、子句太多 | 對**每一句**都成立 |

只做第一層是假的保護：課綱沒收錄的難句照樣過關。
只做第二層又太鈍：一個短句照樣可以是假設語氣。

**通過檢查不等於「這句一定不難」**，只等於「我們量得到的那些都沒超標」。
這句話寫在 UI 上，也寫在這裡——句型清單越完整，那個保證才越有份量。

## 資料長什麼樣

句型跟文法點住在同一張表（`grammar_def`），靠 `kind` 分開：

| kind | 是什麼 | 粒度 |
| --- | --- | --- |
| `point` | 批改時的**錯誤標籤**（`tense`、`articles`） | 要**粗**——切太細的話每個標籤各錯一次，FSRS 排不動 |
| `pattern` | 教學用的**句型**（`there-be`、`conditional-type-2`） | 要**細**——「條件句第二類」跟「第三類」是兩課 |

住在同一張表是因為它們需要的東西一模一樣（可匯入、可編輯、FSRS 排程、
文法頁的進度顯示），而 `grammar_point` 是靠 `(profile_id, point)` 記錄的、
**不是外鍵**——所以句型的掌握度不需要任何新的資料表。

## 匯入格式

```json
[
  {
    "point": "there-be",
    "name": "there is / there are",
    "kind": "pattern",
    "level": "國小高年級",
    "level_ordinal": 1,
    "explanation": "用來說「某個地方有什麼」。單數用 is，複數用 are。",
    "examples": [
      { "text": "There is a book on the desk.", "translation": "桌上有一本書。" }
    ],
    "detectors": [
      {
        "type": "regex",
        "value": "\\bthere\\s+(is|are|was|were)\\b",
        "positive": ["There is a book on the desk.", "There were many people."],
        "negative": ["I put it there.", "Go over there and wait."]
      }
    ]
  }
]
```

只有 `point` 與 `name` 是必要的，但**沒有 `detectors` 的句型偵測不到**，
難度上限對它不生效。

### `level_ordinal` 才是程式看的東西

`level` 是自由文字（`"A2"`、`"N4"`、`"國中七年級"`），字串沒有順序，
程式不能拿它比大小。要判斷「這個句型超過他的程度」就一定要有
`level_ordinal` 這個排得出先後的數字。

**同一個語言只能有一套刻度在生效。** 現在不會撞：內建的 40 條種子是
`kind: "point"` 的 CEFR，課綱句型是 `kind: "pattern"`，而上限只看後者。
哪天有人又匯入一套 CEFR 分級的**句型**，兩套刻度就會打架——
那時要加的是 `scheme` 欄位加上「用哪一套當進度刻度」的設定。

### `positive` / `negative` 不是選配

**一條打錯字的 regex 什麼都比對不到，於是超綱檢查永遠通過，
而畫面上完全正常。** 這跟拿 `strings`（預設只掃 ASCII）去找中文字串
是同一類錯誤：方法自己壞了，結論卻很有信心。

所以每一條偵測器在寫進資料庫之前都會**實跑一次控制組**：

1. 認得的 `type`（目前只有 `regex`）
2. regex 編譯得過
3. **至少一句 `positive`**，而且真的命中
4. `negative` 一句都不能命中

處置隨進來的方式不同：

| 進來的方式 | 一條沒過怎麼辦 |
| --- | --- |
| 匯入檔案 | 丟掉那一條、其餘照收，**並列出丟了哪些** |
| 在文法頁手動編輯 | **拒絕存檔**並說明原因——你正看著對話框，可以馬上改 |
| 編輯器的「試試看」 | 當場回報，不寫入 |

處置不同是因為代價不同：一份 80 條的檔案不該因為一條打錯字而整份失敗，
但手動編輯時默默丟掉你剛寫的規則，只會讓你以為它存進去了。

### regex 的方言

Rust 的 `regex` crate：**不支援** lookahead `(?=)`、lookbehind `(?<=)`
與反向參照 `\1`。它保證線性時間、不會災難性回溯——這一點對
「regex 來自匯入檔案或模型草擬」的情境是硬性條件，不是偏好。

比對時**不分大小寫**，不必自己寫 `[Ii]f`。

跨詞的結構用 `[^.?!]*` 連接，不要用 `.*`——後者會跨過句號，
把兩句話當成一句。

**寧可漏抓，不要誤抓。** 誤抓的代價是好句子被退回去重寫，
使用者只會看到出題一直失敗，而且看不出原因。

## 清單從哪來

**不要把課綱句型表提交進 repo**，理由同 [dictionary-sources.md](dictionary-sources.md)：
課綱本身是教育部的公開文件，但整理好的句型清單多半來自教科書，授權不明。

兩條路。**清單是教學內容，該教什麼、分在哪一級，由人決定**——
這裡刻意沒有「請 AI 產生一批」那條路。

1. **手動一條一條加**（文法頁 →「自己加一個」）。表單裡選「句型」，
   填等級名稱與級數，然後寫偵測規則。每一條規則旁邊有「試試看」，
   打一句話就知道它抓不抓得到、抓到的是哪一段。
2. 自己整理成上面那個 JSON，放本機匯入。要一次帶進幾十條就走這條。

### 「試試看」為什麼要繞到後端

瀏覽器的 `RegExp` 跟 Rust 的 `regex` crate **不是同一種方言**：
JS 支援 lookahead `(?=)` 與反向參照，Rust 這邊完全不支援。
在前端試過就存進去的話，會拿到一條「編輯器裡看起來好好的、
存進資料庫之後編譯失敗」的規則——而它失敗的樣子是安靜的。

所以 `check_detector` 走的是跟存檔、匯入**完全同一個函式**
（`compile_detector`）：那裡說會過，存檔就一定會過。

## 設定與生效

設定頁的「句子難度」有三個上限，**預設全部關閉**：

- 句型程度上限（選單來自資料：`SELECT DISTINCT level_ordinal ... WHERE kind='pattern'`）
- 一句話最多幾個詞
- 一句話最多幾個子句

沒有匯入句型、也沒有設上限時，這整套機制**完全不作用**——
prompt 裡不會多出一段空的難度要求，也不會有任何東西被退回。

## 「我會了」：兩件不同的真話

出題時模型會拿到一份**他已經會的句型**清單。這是整套機制真正貼合個人
的地方——只講什麼不能用，句子會越寫越平；講清楚他會什麼，模型才寫得出
剛好落在他能力範圍內、又不無聊的句子。

那份清單取兩個來源的**聯集**：

| 來源 | 是什麼 | 存在哪 |
| --- | --- | --- |
| 按「我會了」 | 使用者的**主張**：我會這個 | `grammar_point.known_at` |
| 練到撐得過 21 天 | 排程算出來的**證據** | `grammar_point.stability` |

### 為什麼要分開存

原本按「我會了」只是送一次 FSRS 的 Good 評分。但初始 stability 只有
**3.17 天**（`fsrs.rs` 的 w2），而「已學會」的門檻是 **21 天**——
按一次根本到不了。畫面按完仍然顯示「在學」，出題也不知道他會這個句型，
而使用者不知道自己按的那一下去了哪裡。

門檻本身沒有錯（21 天跟詞彙量的定義一致，不能為了讓按鈕有反應就調低）。
錯的是拿一個評分去表達一句話。

### 自評贏過分級上限

標記過「我會了」的句型，**級數再高也不算超綱**：分級上限講的是
「一般人學到哪」，是預設值；使用者親手標記的是事實。

### 答錯不會自動收回自評

誘惑是「他標了會卻答錯，那就把標記收回來」。不這麼做：自評是使用者的話，
只有他能收回；而且錯誤歸因本身是估計的（偵測到的範圍要跟模型指出的
片段重疊才算），拿估計去推翻一句明確的話，方向反了。

取而代之的是**把兩件事都顯示出來**——文法頁上同時看得到「你標記過：
我會了」與「練習中答對 3 次、答錯 5 次」。不一致的時候由人決定。

## 掌握度怎麼累積

句型沿用跟單字卡、文法點同一套 FSRS。**證據來自使用者自己寫的那一句**
（只有「母語 → 目標語」的方向量得到，反方向他寫的是母語）：

| 這一題的狀況 | 記什麼 |
| --- | --- |
| 命中句型，而且被指出來的錯誤**壓在這個句型上** | 答錯 |
| 命中句型，這一題的錯誤都在別的地方（或根本沒錯） | 答對 |
| 命中句型，但有錯誤片段**對不回這一句的位置** | **什麼都不記** |

第三種是重點：對不回位置就不知道錯在哪，那時記「答對」會高估、
記「答錯」會冤枉。**量不到就回 `None`，不要回 0。**

這條路同時補掉了一個舊缺口：翻譯題原本只記 `false`（只採信批改指出來的
錯誤），所以主要做翻譯的人，文法點的 stability 只會被拉低，
沒有任何東西拉高它——練越多看起來越不熟。
缺的不是誠意，是**量得到的證據**。
